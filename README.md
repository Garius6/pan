# Pan (рус. Пан) - пакетный менеджер для языка программирования panos.

Написан на самом panos. Управляет git-зависимостями (semver-диапазоны `^`/`~`/`>=`
поверх git-тегов, единая разрешённая версия пакета на весь граф), раскладывает
их в `модули/` и запускает пакет напрямую через бинарь `panos`.

## Использование

```sh
panos <путь-до-start.pns-пакета-pan> init                       # новый pan.toml + start.pns
panos <путь-до-start.pns-пакета-pan> add <источник> [версия] [синоним]
panos <путь-до-start.pns-пакета-pan> remove <имя>
panos <путь-до-start.pns-пакета-pan> install                    # по pan.lock, без пересчёта версий
panos <путь-до-start.pns-пакета-pan> run [аргументы...]          # из любой поддиректории пакета
panos <путь-до-start.pns-пакета-pan> task <имя> [аргументы...]   # спавнит зависимость-задачу отдельным процессом
panos <путь-до-start.pns-пакета-pan> version <patch|minor|major|X.Y.Z>  # бамп версии + commit + tag, без push
```

`версия` — semver-диапазон (`^1.2.0`, `~1.2.0`, `>=1.0.0`) либо точный
коммит/ветка/тег; без указания — любая версия (берётся самая новая).

`task <имя>` — не импортирует, а спавнит зависимость `<имя>` (уже
добавленную через `add`) отдельным процессом `panos`, читая её
`точка_входа` из собственного `pan.toml` зависимости (пример — соседний
пакет `../codegen/`: `panos <путь-до-pan/start.pns> task codegen файл.pns`).
Задача и библиотека — разные роли одной и той же раскладки в `модули/<имя>/`
(см. ниже): задаче нужна `точка_входа`, библиотеке — файл `индекс.pns`
внутри дерева, который автор зависимости пишет сам (соглашение, как
`lib.rs`/`main.rs` в Rust) — `pan` ничего не генерирует и не дублирует
между этими двумя ролями.

## Файлы

- `pan.toml` — манифест: имя, версия, точка входа (для задач — см. `task`
  выше; библиотеке она не нужна), зависимости.
- `pan.lock` — разрешённый граф зависимостей (генерируется автоматически).
- `модули/<имя>/` — ПОЛНОЕ дерево каждой разрешённой зависимости (минус
  `.git`), не один файл: многофайловые зависимости со связанными
  относительными импортами (`импорт "./соседний"`) иначе не резолвились
  бы. `импорт("имя")` компилятором panos находит библиотеку через
  `модули/имя/индекс.pns` (директория-как-пакет, см.
  `core/resolver.odin::resolve_import_dir_index_path` в основном
  репозитории panos) — тот же принцип, что `index.js`/`__init__.py`.
- Локальный кэш клонов — `~/.pan/cache/`, общий для всех пакетов на машине.

## Модули

- `start.pns` — CLI-диспетчеризация подкоманд.
- `манифест.pns` — `pan.toml`/`pan.lock` (разбор, сериализация, поиск корня пакета).
- `семвер.pns` — парсинг, сравнение и bump (patch/minor/major) semver-версий.
- `гит.pns` — обёртка `git clone`/`checkout`/`ls-remote`/`add`/`commit`/`tag` поверх `ос.выполнить`.
- `граф.pns` — разрешение графа зависимостей, обнаружение конфликтов и циклов.
- `кэш.pns` — локальный кэш и раскладка в `модули/`.

## Известные ограничения (v1)

- `pan add` без синонима при коллизии canonical-имён завершится ошибкой,
  называющей конфликт; повторный вызов с третьим аргументом — явным синонимом —
  разрешает его.
